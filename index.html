Registration & Connection Flow

Register, issue a device key, connect the device, then access it from the manager console.

1

Request Early Access

Submit the registration form. Access is issued after review.

2

Receive Your Account

If approved, you will receive your Tedex username and account password by email. Use these only for the administration console.

3

Create a Device Key

Sign in with -u, then run create-key <user> <device-id> in the manager console. The device key is displayed once; store it securely and never reuse it for another device.

4

Connect the Device

On the Linux device, run the client with -c, your device key, and the same --name. Use --persist for automatic reconnect or -r for service mode.

5

Open a Remote Shell

From the manager, run list, then attach <device-id>. The attached session is an interactive shell on the connected device.

CLI Documentation

Standard syntax for ./client

Administration Console MANAGER 
# Sign in to manage devices and issue enrollment keys
./client --ws wss://anontokenforever.dpdns.org/tedex -u <user> <password>
Issue a Device Key MANAGER 
# Run this from the manager prompt. The key is shown only once.
user@tedex> create-key <user> <device-id>
Connect a Device CLIENT 
# Use the per-device key created above, not the account password.
./client --ws wss://anontokenforever.dpdns.org/tedex -c <user> <device-key> --name <device-id> --persist
Run as System Service (Recommended) SYSTEM SERVICE 
# Installs Tedex as a service and starts it after reboot.
# Requires administrator privileges and systemd.
sudo ./client --ws wss://anontokenforever.dpdns.org/tedex -c <user> <device-key> --name <device-id> -r
Uninstall CLIENT 
# Remove the service installed with -r. Use the same device ID.
sudo ./client --uninstall --name <device-id>
Transport Options NETWORK 
# Recommended for Internet access: verified WSS endpoint
./client --ws wss://anontokenforever.dpdns.org/tedex -u ...

# Direct TCP: use only on a trusted/private network
./client -s <host-ip> -p <port> -u ...

Manager Interactive Shell

After logging in as Client Manager, you enter an interactive shell to manage your connected devices.

Example Session INTERACTIVE 
$ ./client --ws wss://anontokenforever.dpdns.org/tedex -u user password
manager user — type help

user@tedex> create-key user server-prod-01
OK key for user/server-prod-01 (save it now, shown once):
tdk_<enrollment-key>

user@tedex> list
1/10 device(s): online=1 offline=0 never-connected=0
  - server-prod-01 [online] - <address>

user@tedex> attach server-prod-01
ATTACHED server-prod-01

user@server-prod-01:~$ hostname
server-prod-01

user@server-prod-01:~$ exit
session ended — reconnecting...

user@tedex> remove server-prod-01
OK removed server-prod-01

list

Shows known devices, quota usage, and online, offline, or never-connected status.

attach <device_id>

Open an interactive shell on a connected device. Typing exit ends that remote shell session.

create-key <user> <device_id>

Issue a unique enrollment key for one device. Copy it directly to that device and keep it private.

remove <device_id>

Revoke the device key and known-device entry. A connected service client is instructed to stop and uninstall.

quit / exit

Close the manager console. When attached to a device, exit the remote shell first.

Tip: After create-key, the enrollment key is displayed only once. If it is lost, remove the device entry and create a new key.

Security & Service Controls

Practical controls for day-to-day remote administration

TLS

Verified Connections

The hosted endpoint uses WSS with certificate-chain and hostname validation. Always confirm the connection URL before entering credentials.

KEY

Scoped Device Keys

Issue a separate key for each device. Revoke one device without replacing your account password or disturbing other devices.

STATUS

Visible Device Status

Use the manager console to review known devices, connection state, and quota before attaching to a shell.

SHA

Checksummed Downloads

Each release provides SHA-256 digests for the x86_64 and ARM64 client binaries. Verify the digest before installation.

RECOVER

Recovery Controls

--persist restores interrupted sessions, while -r provides reboot-safe service operation on supported systemd hosts.

AUTH

Authorized Access Only

Connect only devices you own or are explicitly authorized to administer. Treat enrollment keys like passwords.
